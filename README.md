# finfriends-prd-to-srs

핀프렌즈(FinFriends) PRD를 **축약형 SRS 문서로 변환**하는 작업 저장소.

---

## 1. 작업 목표

> **표준 전문(全文)을 따르는 풀 버전 SRS를 만드는 것이 목표가 아니다.**
> 예시 사례로 확보한 `SRS_example_AD-Core-Platform.md`와 **동일한 축약 포맷**으로 변환하는 것이 목표다.

### 1-1. 기본 원칙 — 예시 SRS 포맷을 기준선으로 삼는다

변환 결과물은 `SRS_example_AD-Core-Platform.md`의 **목차 구성 · 표 구조 · 서술 밀도 · 분량 감각**을 그대로 따른다.
ISO/IEC/IEEE 29148:2018은 이 축약 포맷의 **근거이자 확장 시 참조하는 기준**이지, 전 조항을 빠짐없이 채워야 하는 체크리스트가 아니다.

기준선이 되는 예시 SRS의 구성:

| 절 | 구성 |
|---|---|
| 1 | 서론 — 목적 / 범위 / 정의·약어 |
| 2 | 이해관계자 — 역할 · 부서 · 책임 |
| 3 | 시스템 맥락 및 인터페이스 — 클라이언트 · 내부 서비스 · 외부 시스템 |
| 4 | 구체적 요구사항 — 4.1 기능 / 4.2 비기능 |
| 5 | 추적성 매트릭스 — 요구사항 ID ↔ 모듈 ↔ 구현 클래스 ↔ 테스트 케이스 |
| 6 | 부록 — API 목록 / 데이터 모델 / 비즈니스 규칙 / DB 스키마 |
| 7 | 향후 개선 사항 |

요구사항 표는 **9열 고정**: `ID · 제목 · 출처 · 우선순위 · 유형 · 검증 방식 · 인수 기준 · 상태 · 담당자`
규모 감각: 기능 8건 + 비기능 5건 = **13건 / 약 286줄**.

### 1-2. 확장 원칙 — 벗어나는 내용만, 표준 구성에 따라

PRD에 담긴 내용 중 **예시 SRS의 범위로는 담기지 않는 것**이 있을 때에만,
**해당 부분에 한해** ISO/IEC/IEEE 29148:2018의 표준 포맷 구성을 따라 절을 확장한다.

- 확장은 **부분적**이다 — 한 항목이 넘친다고 문서 전체를 풀 버전으로 승격하지 않는다.
- 확장 시에는 **임의로 절을 만들지 않고** 29148의 해당 조항 구성을 따른다.
- 예시 SRS 포맷 안에 무리 없이 들어가는 내용은 **확장하지 않는다.**

### 1-3. 확장이 필요할 것으로 보이는 후보

PRD 검토 결과, 예시 SRS의 범위를 넘어서는 것으로 판단되는 항목:

| PRD 위치 | 내용 | 예시 SRS에 없는 이유 |
|---|---|---|
| §3 | 사용자 스토리 8개 + 인수 기준 43개(정상 26 · 예외 AC-E 17) | 예시 SRS는 인수 기준을 요구사항 표의 한 칸으로 압축 — 예외 경로를 담을 자리가 없음 |
| §7-4 | **ADR 8건** — 결정 · 기각한 대안 · 서 있는 가설 · 판정 실험 · 뒤집히는 조건 · 대가 | 예시 SRS에 결정 기록 절이 없음 |
| §4-1-1 | 선행 의존성 · 스프린트 환산 · 크리티컬 패스 | 예시 SRS의 요구사항 표에 의존성 열이 없음 |
| §1-3-1 · §3-0 | PASS / HOLD / FAIL 3구간 판정, 인터뷰 지표 `k/8` 정수 판정, 코딩 규칙(κ ≥ 0.6) | 검증 방식이 "QA 검증" 수준으로만 기술됨 |
| §5-1 | 규제 9조항 — 성능·가용성보다 우선하는 상수 | 예시 SRS의 비기능 요구사항은 Security 1행뿐 |
| §8 | 실험 설계 · 벤치마크 · 롤아웃 · 선결 과제 순서 | 예시 SRS에 검증 계획 절이 없음 |
| §7-2 · §7-3 | 리스크 · 가정 · 의존성 | 예시 SRS에 해당 절이 없음 |
| 문서 지위 | 기준선 실측 전(확보 시점은 §1-2에 명시) · 인용 금지 10항목(§9-2) | 예시 SRS는 확정 사양·측정 완료를 전제로 작성됨 |

> 위 표는 **착수 시점의 가설**이며, 변환 작업 중 확정한다.
> 최종 판단 기준은 **"예시 SRS 포맷 안에 손실 없이 들어가는가"** 하나다.

## 2. 변환 시 승계해야 할 제약

원본 PRD가 명시한 제약은 SRS로 옮길 때에도 유지한다.

1. **결정과 수치를 구분한다** — §4 기능 우선순위 · §5-1 규제 상수 · §7-1 범위 · §7-4 ADR 8건은 **확정된 결정**이므로 SRS에 확정 사양으로 옮긴다. 반면 §1-2·§1-3의 **기준선은 실측 전**이므로, 목표값을 달성한 성과처럼 옮겨 적지 않는다.
2. **성능·가용성은 AC 역산 상한** — PRD §5-2는 확정 SLO가 아니라 *"이 값을 넘으면 해당 AC가 성립하지 않는다"* 는 상한이다(ADR-007). SRS의 비기능 인수 기준으로 그대로 쓰되, 그 지위를 함께 적는다.
3. **인용 금지 10항목** — PRD §9-2의 금지선을 그대로 승계한다. 특히 **「소비 순간 자동 개입」은 폐기된 기능**이며 로드맵에도 없다(ADR-002).
4. **미대응 상태 노출** — 사전 개입 사각지대(Pain C5)는 F8 계획 카드로 **부분 대응**이며 **자동 발동은 0개**다. 해소된 것처럼 기술하지 않는다.
5. **등급 표기 승계** — `[A]` `[관측]` `[추론]` `[검증 대기]` `[설계 확정]` `✍️[합성 가설]` `🧪[모의]`.
