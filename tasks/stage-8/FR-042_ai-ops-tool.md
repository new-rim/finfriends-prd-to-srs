## 🎯 Summary

- **기능명:** 회고 문장 풀 확장을 돕는 **운영자 전용 AI 도구** — `(ops)` 경계 · 모델 교체 가능한 레지스트리 · 프롬프트 화이트리스트 · 초안 생성 · 승인 상태기계.
- **목적:** X-7의 해소 — 아동의 소비·실천 데이터를 외부 AI에 보내면 **규제 계층 1과 충돌한다.** 그래서 AI를 **기능이 아니라 도구**로 두고, **경계 자체를 요구사항으로** 만든다.
- **AC 6건을 진다** — REQ-AI-001~005 전부.
- ⚠️ **`AI_ENABLED=false`가 기본값이다.** 이 값이 `false`여도 **기준 SRS 요구사항 35건 중 성립하지 않는 것이 하나도 없다**(§4.3).

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 아동·보호자 요청이 AI를 기다리지 않는다 (AC-A1.2)**
- **Given:** 운영 1일치 요청 로그 / **When:** 감사한다
- **Then:** 아동·보호자 요청 중 **외부 AI 호출을 기다린 요청 0건**.

**Scenario 2: 모델 교체 (AC-A2.1)**
- **Given:** `AI_MODEL_ID`를 다른 모델로 변경 / **When:** 재배포한다
- **Then:** **코드 변경 0줄로 동작**하고 초안 생성이 성공한다.

**Scenario 3: 프롬프트 금지 변수 (AC-A3.1)**
- **Given:** 프롬프트에 `childName`·`amount`·`merchant`를 넣은 코드 / **When:** 빌드한다
- **Then:** **빌드 실패** · **허용 변수 목록을 출력**한다. *(강제는 `FR-005`의 G6)*

**Scenario 4: 발신 페이로드 감사 (AC-A3.2)**
- **Given:** 실제 생성 요청 100건의 발신 페이로드 / **When:** 표본 검사한다
- **Then:** 아동 식별정보·금액·가맹점명 **0건**.

**Scenario 5: 승인 전 미배정 (AC-A4.1)**
- **Given:** AI가 생성한 초안 20건 / **When:** 아동이 회고 화면을 연다
- **Then:** **승인 전 초안은 배정되지 않는다**(0건).

**Scenario 6: 전면 장애 격리 (AC-A5.1)**
- **Given:** Gemini API가 **전면 장애** / **When:** 아동·보호자가 앱을 사용한다
- **Then:** **어떤 화면도 저하되지 않는다** · 가용성 지표에 **반영되지 않는다**.

## ⚙️ Technical & Non-Functional Constraints

- 🔴 **규제:** AI 호출은 **`app/api/ops/**` 아래에서만**(REQ-AI-001). `(child)`·`(guardian)` 경로의 AI SDK import **0건**
- 🔴 **규제:** 프롬프트 허용 입력 **4종뿐**(REQ-AI-003 · C-TEC-017) — 게이트 G6가 빌드에서 막는다
- 🔴 **격리:** AI 장애가 아동·보호자 화면에 **영향 0** · 가용성 지표에서 분리(REQ-AI-005)
- **교체 가능성:** 모델 하드코딩 0건 · 직접 HTTP 호출 0건(REQ-AI-002)
- **비용:** 월 호출 상한(REQ-NF-016 · CON-RES-03)
- **기본값:** `AI_ENABLED=false` — **켜지 않아도 요구사항 손실이 없다**
