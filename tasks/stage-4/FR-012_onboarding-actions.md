## 🎯 Summary

- **기능명:** 보호자 온보딩 5단계의 쓰기 액션 3종을 구현한다 — **매 단계 커밋** · **동의 기록(버전 포함)** · **카드 신청 실패 시 입력값 24h 보존**.
- **목적:** REQ-FUNC-007의 성립 조건은 *"단계 저장을 **세션 메모리에 두지 않고** 매 단계 Server Action으로 커밋"* 이다. 세션에 두면 만료 시 사라지고 AC-8.1(재입력 0건)이 깨진다.
- **왜 한 이슈인가:** 세 액션이 **FR-008의 C-01 계약 하나**를 공유하고, 온보딩 퍼널이라는 **같은 완료 판정**(AC-8.3 소요·이탈률)을 진다.

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 단계 재개 (AC-8.1)**
- **Given:** 온보딩 5단계 중 2단계까지 진행
- **When:** 종료 후 다음 날 재진입한다
- **Then:** **직전 단계에서 이어서 시작** · 재입력 항목 **0건**.

**Scenario 2: 카드 신청 외부 API 실패 (ACE-8.1)**
- **Given:** 카드 신청 단계에서 외부 API 실패
- **When:** 오류가 반환된다
- **Then:** **입력값이 24시간 보존**되고 재진입 시 재입력 **0건** · 오류 사유가 **사용자 언어**로 표시된다.

**Scenario 3: 세션 만료 재개 (ACE-8.2)**
- **Given:** 온보딩 중 세션 만료
- **When:** 재로그인한다
- **Then:** **직전 완료 단계에서 재개**되고 **동의 단계는 재확인**한다 — 동의는 캐시하지 않는다.
  *(재확인 경로 자체는 FR-011이 구현한다. 이 이슈는 **단계 복원**까지다.)*

**Scenario 4: 동의 버전 기록**
- **Given:** 동의 문구 v1로 동의를 완료한 보호자
- **When:** 동의 기록을 조회한다
- **Then:** **어느 버전에 동의했는지**가 남아 있다.

## ⚙️ Technical & Non-Functional Constraints

- 🔴 **규제:** 동의 기록에 **버전 포함** (REQ-NF-008) — 문구 변경 이력과 대조 가능해야 한다
- 🔴 **신뢰:** 카드 신청 실패 시 입력값 **24h 보존** — 보호자가 처음부터 다시 입력하면 온보딩 이탈로 직결된다(AC-8.3 이탈률 ≤ 30%)
- **경계:** 제휴사 호출은 **Server Action 내 `fetch`** — 웹훅(FR-019)과 방향이 반대다
- **멱등:** 3종 모두 `idempotencyKey` 필수 (FR-008 C-01)
- **범위:** 화면은 UX-002, 동의 판정은 FR-011이 한다

## ⚠️ 이 이슈가 온보딩 이탈을 좌우한다

AC-8.3은 **3단계 이탈률 ≤ 30%** 를 요구한다. 카드 신청(보통 4~5단계)에서 실패했을 때 **처음부터 다시**가 되면 그 수치를 맞출 수 없다. 24h 보존이 편의 기능이 아니라 **생존 조건**인 이유다.
