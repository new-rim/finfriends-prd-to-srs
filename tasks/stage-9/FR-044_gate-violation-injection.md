## 🎯 Summary

- **기능명:** `FR-005`가 만든 게이트 7종 각각에 **위반 코드를 주입해 빌드가 실패하는지** 확인한다.
- **목적:** 릴리스 게이트 **RG-T1**의 단독 근거다. *"게이트 7종 위반 주입 테스트 **7/7 실패 확인**"* 이 안 되면 **릴리스 중단 — 규제 강제 수단이 작동하지 않는 상태**다.
- **왜 단독 이슈인가:** **AC 8건을 혼자 진다.** 개정 3.0 §7이 *"무엇을 더해도 상한을 넘는다"* 로 **절대 병합 금지**한 이슈다.

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 7/7 빌드 실패 (AC-T11.1 · RG-T1)**
- **Given:** 게이트 7종 각각의 위반 코드
- **When:** 빌드한다
- **Then:** **7종 모두 빌드 실패**(7/7). 하나라도 통과하면 **릴리스 중단**.

**Scenario 2: 라우트 그룹 밖 아동 화면 (AC-T1.1)**
- **Given:** `(child)` 밖에 만든 아동 화면 / **When:** 빌드한다 / **Then:** **G3가 실패**시킨다.

**Scenario 3: 위반 위치 출력 (AC-T2.1)**
- **Given:** Client Component의 `@/db/request` import / **When:** 빌드한다
- **Then:** 빌드 실패 · **위반 파일·줄이 로그에 출력**된다.

**Scenario 4: 멱등 키 부재 (AC-T3.2)** — `idempotencyKey` 없는 Action → **G4 빌드 실패**.

**Scenario 5: 스타일 이탈 (AC-T12.1)** — 새 CSS·인라인 `style` → **빌드 실패**.

**Scenario 6: 파괴적 DDL (AC-T15.1)** — `DROP COLUMN` → **G7 빌드 실패 + 분할 지침 출력**.

**Scenario 7: AI 경계 (AC-A1.1 · AC-A3.1)** — `(child)`의 AI SDK import → **G6 실패** / 프롬프트 금지 변수 → **G6 실패 + 허용 목록 출력**.

**Scenario 8: 로컬 동등성 (§9.1)**
- **Given:** 같은 위반 코드 / **When:** **로컬에서** 빌드한다
- **Then:** **동일하게 실패**한다 — CI만 막고 로컬은 통과하는 상태가 아니다.

## ⚙️ Technical & Non-Functional Constraints

- 🔴 **RG-T1의 단독 근거** — 7/7이 아니면 **릴리스 중단**이다. 부분 통과라는 판정이 없다
- 🔴 **로컬에서도 실패해야 한다** — §9.1이 REQ-NF-010을 재정의하며 *"강제 지점이 CI보다 넓어졌다"* 고 적은 부분이다
- **격리:** 위반 코드가 실제 코드베이스에 섞이면 안 된다 — 별도 픽스처로 관리
- **반복 가능:** 게이트를 고칠 때마다 돌린다. 수동 절차면 안 돈다
- **범위:** 게이트 구현은 `FR-005`. 이 이슈는 **그것이 실제로 막는지**만 본다
