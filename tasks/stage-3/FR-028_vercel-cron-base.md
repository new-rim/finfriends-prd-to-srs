## 🎯 Summary

- **기능명:** Vercel Cron의 **공통 진입 인증**을 세우고, 그 위에 **외부에서 두드려야 의미가 있는 배치 2종**(가용성 프로브 · 원가 집계)을 올린다.
- **목적:** §11 분담 규칙 2 — *"외부 호출이 있으면 Vercel Cron으로 나온다."* 프로브는 **외부에서 두드려야** 가용성 판정이 되고, 원가는 **청구 API 외부 호출**이 본체다.
- **왜 한 이슈인가:** `CRON_SECRET` 인증은 **계약**이고, 프로브·원가는 그 계약을 쓰는 **첫 두 사용자**다. 함께 만들어야 계약의 형태가 실제로 검증된다.

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 시크릿 없는 호출 거부**
- **Given:** `CRON_SECRET` 헤더가 없거나 틀린 요청
- **When:** `/api/cron/probe`를 호출한다
- **Then:** **거부**된다 — 배치 임의 실행 경로가 생기지 않는다.

**Scenario 2: `/api/health`는 인증 없이 응답**
- **Given:** 인증 없는 프로브 요청
- **When:** `/api/health`를 호출한다
- **Then:** **상태만** 반환한다 — 데이터가 새지 않는다.

**Scenario 3: 실행 시간 상한 (REQ-TEC-010)**
- **Given:** 프로브·원가 배치 실행
- **When:** 소요를 잰다
- **Then:** 함수 실행 상한의 **60% 이내**다.

**Scenario 4: 하트비트 기록**
- **Given:** 프로브·원가 배치가 성공적으로 완료
- **When:** `batch_heartbeats`를 조회한다
- **Then:** 두 배치 모두 **최근 성공 시각이 갱신**되어 있다.

## ⚙️ Technical & Non-Functional Constraints

- 🔴 **보안:** `CRON_SECRET`은 **Production 스코프만** · 유출 시 배치 임의 실행 (§10.2)
- **분담:** 외부 호출이 있는 배치만 여기 있다 — DB 안에서 끝나는 집계는 `pg_cron`(FR-024~033)이 한다 (§11 규칙 1·2)
- **성능:** Vercel 배치는 함수 상한의 **60% 이내** (REQ-TEC-010)
- **가용성:** 프로브는 **외부에서 두드려야** 의미가 있다 — 내부 호출로 대체하면 REQ-NF-004·005를 판정할 수 없다
- **범위:** 알림 발송·침묵 감지는 **FR-032**, DLQ 재처리·미접속 알림은 **FR-029**이 한다
