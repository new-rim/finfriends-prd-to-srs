## 🎯 Summary

- **기능명:** 별도 CI가 없으므로 **빌드가 유일한 강제 지점**이다(C-TEC-014). 게이트 러너와 7종 검사를 만든다.
- **목적:** SRS §13.1이 *"첫 커밋부터 켜져 있어야 위반이 쌓이지 않는다"* 고 못 박은 지점이다. **나중에 켜면 이미 쌓인 위반을 전부 걷어내야 한다.**
- **AC 8건을 진다** — Stage 3에서 가장 무거우며, 개정 3.0의 46개 이슈 중 AC 부하 4위다.

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 라우트 그룹 밖 아동 화면 (AC-T1.1)**
- **Given:** 아동 화면을 `(child)` 그룹 **밖에** 새로 만든 브랜치
- **When:** 빌드한다 / **Then:** **G3가 빌드를 실패**시킨다.

**Scenario 2: 런타임 경계 침범 (AC-T2.1)**
- **Given:** Client Component에서 `@/db/request`를 import한 코드
- **When:** 빌드한다 / **Then:** **빌드 실패** · 위반 **파일·줄이 로그에 출력**된다.

**Scenario 3: 멱등 키 없는 액션 (AC-T3.2)**
- **Given:** `idempotencyKey`를 받지 않는 Server Action
- **When:** 빌드한다 / **Then:** **G4가 빌드 실패**.

**Scenario 4: 스타일 이탈 (AC-T12.1)**
- **Given:** 새 CSS 파일 또는 인라인 `style` 추가 / **When:** 빌드한다 / **Then:** **빌드 실패**.

**Scenario 5: 파괴적 DDL (AC-T15.1)**
- **Given:** `DROP COLUMN`을 포함한 마이그레이션
- **When:** 빌드한다 / **Then:** **G7이 빌드 실패** · **분할 지침을 출력**한다.

**Scenario 6: AI 경계 (AC-A1.1 · AC-A3.1)**
- **Given:** `(child)`에서 AI SDK를 import한 코드 / 프롬프트에 `childName`·`amount`·`merchant`를 넣은 코드
- **When:** 빌드한다 / **Then:** **G6가 각각 빌드 실패** · 후자는 **허용 변수 목록을 출력**한다.

**Scenario 7: 게이트 실행 흔적 (AC-T11.2)**
- **Given:** 임의의 배포 로그 / **When:** 게이트 실행 줄을 찾는다 / **Then:** **모든 배포에 존재**한다.

## ⚙️ Technical & Non-Functional Constraints

- 🔴 **이중 호출 필수** — `prebuild`만 걸면 패키지 매니저 정책 차이로 **조용히 건너뛰어진다**
- 🔴 **G1·G2·G6은 `// gate-ignore`를 인정하지 않는다** — 규제 계층 1·2이기 때문이다
- **화이트리스트:** 예외는 주석이 아니라 **승인된 목록**으로만. 변경이 커밋에 남아야 감사가 성립한다
- **성능:** 게이트는 **모든 빌드마다** 돈다. 전체 소스 스캔이 빌드 시간을 지배하지 않도록 한다
- **범위:** 이 이슈는 **게이트를 만든다.** 7/7 위반 주입 검증은 **FR-035**가 정식으로 한다
