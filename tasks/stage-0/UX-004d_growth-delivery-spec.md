## 🎯 Summary

- **기능명:** 보호자가 보는 전달 화면 4종 — **성장 나무 · 정체 원인 · 월간 숲 · 소비 내역**의 디자인 명세.
- **목적:** 원본이 스스로 적었다 — *"AC 12건 중 **6건이 인터뷰 rubric(M 유형)** 인 것이 그 증거다. **「5초 노출 후 회상 ≥ 6/8」 같은 판정은 코드가 아니라 화면이 통과시킨다**."* 그 화면 구성이 이 태스크다.
- **왜 이 건의 분리 효과가 가장 큰가:** 원본은 `FR-026`(집계 배치)·`FR-030`(나무 조회) 뒤라 **D+42 착수 · 여유 1일**이었다. 임계에 가장 가까운 화면인데, 그 안의 절반이 **쿼리를 기다릴 이유가 없는 판단**이다.

> **범위 경계 한 줄** — 배치 산출값 렌더·캐시 정책·§8 예산 준수는 짝 구현이 진다. 이 태스크는 **기본 상태에서 무엇이 어떤 순서로 보이는가**를 확정한다. 인터뷰 rubric은 그것으로 판정된다.

## ✅ Task Breakdown (실행 계획)

**성장 나무 — 5초에 읽히는 기본 상태**
- [ ] 🔴 **상세를 펼치지 않은 기본 상태**의 정보 배치 확정 — 판정 대상이 이 상태다 (AC-1.1)
- [ ] 🔴 **「나무가 자란 이유 = 실천」** 으로 읽히는 표현 — *"퀴즈를 많이 풀어서"* 만 읽히면 **실패**다 (AC-1.2)
- [ ] **「승인 대기 N건」 Badge** 배치 — *"이번 주엔 안 했구나"* 라는 반대 결론을 막는 자리 (AC-6.2)
- [ ] **실천 0건 빈 상태** 문구 — *"아직 기록이 없어요 + 첫 실천 안내"* (ACE-1.1)

**정체 원인 — 조건 단위 표시 규칙**
- [ ] 🔴 **미충족 조건 전부 표시** · **「가장 적게 남은 조건」을 최상단**에 두는 정렬 규칙 (ACE-3.1)
- [ ] 학습 초과 충족 시 **「실천 N회 남음」** 문구 원문 (AC-2.2 · ACE-2.3)
- [ ] 🔴 **오귀인·앱 불신을 유발하지 않는 문구** — 정체를 아동의 실패로 읽히게 하지 않는다 (AC-3.2)

**월간 숲 — 60초에 변화 3개**
- [ ] `Tabs`(월 선택) 배치 · 월 전환의 사용자 표현
- [ ] 🔴 **전월 없음 → "다음 달부터 비교할 수 있어요"** 대체 문구. **델타 0으로 렌더하지 않는다** (ACE-1.2)
- [ ] 🔴 **「이번 달 획득 별」이 스크롤 없이** 보이는 배치 — 잔액이 0이어도 (AC-1.4)
- [ ] **60초 내 전월 대비 변화 3개**를 지목할 수 있는 배치 (AC-1.3)

**소비 내역**
- [ ] **전월 대비 증감액을 상단에** 두는 배치 · 업종별 집계 표현

**공통**
- [ ] 4화면 전건을 **§6.8 컴포넌트 대응표**에 사상 — 새 컴포넌트 이전에 표에서 찾는다
- [ ] 정보량이 **§8.1 렌더 예산 안**에 들어오는지 검토 — 5초에 읽히는 것과 빠른 것은 같은 방향이다
- [ ] 빈 상태·로딩·오류 문구 전 화면 전수 확정
- [ ] `UX-001` 토큰만으로 표현 — 임의 색상 리터럴 0건

## ⚙️ Technical & Non-Functional Constraints

- **FR 선행 없음** — `FR-030`의 반환 타입·`FR-026`의 스냅샷 구조에 의존하는 결정을 넣지 않는다. 필요해지면 짝 구현으로 넘긴다
- **재계산 금지 전제:** 화면이 조건·퍼센트·집계를 다시 계산한다는 전제의 설계를 하지 않는다
- **델타 0 금지:** 전월 데이터가 없을 때 0으로 그리는 설계는 **금지**다 — 없음과 변화 없음은 다른 사실이다 (ACE-1.2)
- **정보량 = 예산:** 나무 기본 상태에 무엇을 넣을지가 p95 1,250ms를 결정한다 (§8.1)
- **스타일:** `UX-001` 토큰 · `src/components/ui/**`만 (게이트 G5의 설계 쪽 절반)

- [ ] 성장 나무의 **기본 상태 정보 배치**가 확정되었는가? (5초 판정 대상)
