## 🎯 Summary

- **기능명:** 아동의 첫 화면 두 개 — **학습·퀴즈**와 **첫 보상 루프 5분 이내** 온보딩의 디자인 명세.
- **목적:** 아동이 **5분 안에 첫 별을 받는** 구성은 화면 순서·정보량·강조 지점이 정해져야 성립한다. 그것은 서버 경계 없이 확정할 수 있다.
- **왜 분리되나:** 원본은 `FR-011`(동의 게이트)·`FR-014`(학습 원고) 뒤에 있어 D+28에 착수한다. 그런데 **5분 루프 설계는 원고 조회 API를 기다릴 이유가 없다.**

> **범위 경계 한 줄** — 원고 렌더·⭐ 지급 동작·계측은 짝 구현이 진다. 이 태스크는 **무엇을 어떤 순서로 어떻게 강조할지** 확정한다.

## ✅ Task Breakdown (실행 계획)

**첫 보상 루프 — 5분 이내 구성**
- [ ] 🔴 **진입 → 첫 학습 → 첫 ⭐** 까지의 화면 순서와 **단계별 예상 소요**를 확정
- [ ] 각 단계의 정보량 상한 — 5분을 넘기는 원인은 대개 한 화면에 너무 많은 것을 넣는 것이다
- [ ] 🔴 **첫 별 획득 순간의 강조 표현** — 이후 루프의 기대를 만드는 지점
- [ ] ⭐ 지급과 **나무 진행도를 한 화면에서** 보여 주는 레이아웃 (AC-2.1)

**학습·퀴즈 화면**
- [ ] `Card` · `RadioGroup` · `Progress` 조합으로 화면 구성 (§6.8 대응표)
- [ ] 퀴즈 정답·오답 피드백의 **표현과 문구** — 아동에게 실패로 읽히지 않게
- [ ] 🔴 **「불리기 곧 열려요」 안내** 문구 원문과 배치 — 닫힌 영역이 **결함으로 보이지 않게** (AC-2.4)
- [ ] 4영역 명칭을 **`UX-001`의 아동용 문구와 동일하게** 고정 (CON-REG-02)

**공통**
- [ ] 아동 접근성 — 터치 타깃 **≥ 44px** · 대비 **4.5:1** 을 명세에 수치로 박는다
- [ ] 빈 상태·로딩·오류 문구를 **전 화면 전수** 확정
- [ ] `UX-001` 토큰만으로 표현되는지 확인 — 임의 색상 리터럴 0건
