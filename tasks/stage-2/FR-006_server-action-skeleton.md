## 🎯 Summary

- **기능명:** 모든 Server Action이 통과할 **5단계 실행 골격**과, 그 골격이 쓰는 **멱등 키 유틸** · **캐시 태그 상수**를 만든다.
- **목적:** SRS §13.1이 *"첫 Server Action이 이 래퍼 없이 작성되면 나머지가 그것을 따라간다"* 고 적은 지점이다. **12개 Command 이슈가 이 골격을 복사해 채운다.**
- **왜 한 이슈인가:** 골격 · 멱등 키 · 캐시 태그는 **셋이 함께 있어야 골격이 성립한다.** 멱등 키 없는 골격은 ①단계를 못 쓰고, 태그 상수 없는 골격은 ⑤단계를 못 쓴다.

## ✅ Task Breakdown (실행 계획)

**(구 FR-026) 공통 골격 — 5단계**
- [ ] **① 입력 검증** — zod 스키마 필수. Server Action은 **공개 엔드포인트**이므로 검증 없는 인자는 그대로 외부 입력이다
- [ ] **② 동의 재확인** — `withGuardian()` 트랜잭션 **안에서** 조회 · **캐시 금지**(REQ-TEC-006). 실제 `assertConsentCompleted`는 FR-011이 만들며, 여기서는 **호출 지점만** 골격에 뚫는다
- [ ] **③ 원자 기입** — FR-004의 `grantStarAtomically`를 호출하는 자리. 단일 트랜잭션 · 왕복 없음
- [ ] **④ 계측 동시 적재** — `recordEvent`를 **같은 트랜잭션**에 넣는다. 지급됐는데 이벤트가 없으면 WPA가 실제보다 낮게 나온다(§9.4.6 H1)
- [ ] **⑤ 선택적 재검증** — `revalidateTag`로 **자기가 바꾼 태그만**. `revalidatePath("/")` 한 줄이 800ms 예산을 통째로 날린다
- [ ] 골격을 **함수 하나로 감싸는 형태**로 노출해, 액션 작성자가 단계를 빠뜨릴 수 없게 한다 (이후 게이트 G4가 이 시그니처를 검사한다)

**(구 FR-027) 멱등 키**
- [ ] **UUIDv7 발급 클라이언트 유틸** — 시간 정렬 가능한 v7을 쓴다
- [ ] 발급·전달 규약 — **클라이언트가 만들어 서버로 보낸다.** 서버가 만들면 재시도가 새 키가 되어 멱등이 깨진다
- [ ] 오프라인 큐(FR-039)가 **항목별로 각각의 키**를 쓸 수 있는 형태로 노출

**(구 FR-028) 캐시·재검증 태그**
- [ ] 태그 **상수 모듈** — `stars:{childId}` · `tree:{childId}` · `forest:{childId}` · `approvals:{guardianId}` · `consent:{guardianId}` · `plan:{childId}` · `card:{childId}` · `guardian:{id}` · `content` · `sentencePool`
- [ ] `noStore()` 적용 대상 규약 — **동의 상태 · 별 잔액 · 승인 대기 건수**
- [ ] 태그 문자열을 **직접 쓰지 못하게** 상수로만 노출 (오타 하나가 조용한 캐시 미스가 된다)

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 지급~반영 지연과 태그 범위 (AC-T16.1)**
- **Given:** 골격을 통과하는 ⭐ 지급 액션
- **When:** 실행부터 화면 반영까지를 잰다
- **Then:** **p95 ≤ 800ms**이고, 무효화된 태그가 **해당 아동 범위로 한정**된다.

**Scenario 2: 멱등 키 필수 (AC-T3.2의 전제)**
- **Given:** 골격을 쓰는 임의의 Server Action
- **When:** 입력 스키마를 검사한다
- **Then:** `idempotencyKey`가 **필수 필드**로 존재한다. *(빌드 실패 강제는 FR-005의 게이트 G4가 한다)*

**Scenario 3: 계측 동시 적재**
- **Given:** 골격을 통과한 쓰기 1건
- **When:** 트랜잭션이 커밋된다
- **Then:** 원장 기입과 이벤트 적재가 **같은 트랜잭션에서** 확정된다 — 한쪽만 남는 상태가 없다.

## ⚙️ Technical & Non-Functional Constraints

- **성능:** ⭐ 지급~화면 반영 **p95 ≤ 800ms** (REQ-TEC-016 · §8.2). `revalidateTag` 구간이 예산의 **39%** 를 쓴다
- **규제:** 동의 상태는 **캐시하지 않는다** (CON-REG-01) — 캐시하면 REQ-NF-008(100% 차단)이 읽기 경로에서만 성립한다
- **경계:** 이 골격 **밖에서 도는 쓰기는 게이트 G4에서 빌드 실패** (FR-005가 강제)
- **멱등:** `idempotencyKey`는 **클라이언트 생성 UUIDv7** — 서버 생성 금지
- **서버리스:** 인스턴스가 임의 시점에 종료되므로 「나중에 마저 하기」가 성립하지 않는다 — ③④는 한 트랜잭션이어야 한다

## ⚠️ 이 이슈의 무게

**SRS §13.1이 지목한 「따라가는」 지점이다.** 첫 액션이 이 골격 없이 작성되면 나머지 11개가 그것을 따라가고, 되돌리려면 **12개 이슈를 다시 연다.** 골격의 형태를 확정하기 전에는 Stage 4 이후를 착수하지 않는다.
