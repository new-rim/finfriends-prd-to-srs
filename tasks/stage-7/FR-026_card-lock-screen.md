## 🎯 Summary

- **기능명:** 카드가 아직 없거나 배송 대기인 상태에서 **카드가 필요한 기능만 잠그고 나머지는 열어 둔다.**
- **목적:** REQ-FUNC-015의 성립 조건 — *"`PARTNER_CARDS.state`로 잠금 분기. 라우트 그룹은 그대로 두고 **컴포넌트 단위 잠금**."* 라우트를 막으면 아동이 **아무것도 못 하는 상태**가 된다.
- **핵심 판정:** 카드 배송 대기 중에도 **학습·퀴즈·별 획득은 가능**해야 한다(AC-8.2).

## ✅ Task Breakdown (실행 계획)

- [ ] `PARTNER_CARDS.state`를 읽어 **잠금 여부를 판정**하는 공통 컴포넌트/훅
- [ ] 🔴 **컴포넌트 단위 잠금** — 라우트를 막지 않는다. 화면은 열리고 **카드가 필요한 부분만** 잠긴다
- [ ] 🔴 **잠기지 않아야 하는 것을 명시** — 학습 · 퀴즈 · 별 획득 · 나무 · 위시리스트 저축(AC-8.2)
- [ ] **잠기는 것** — 계획 카드 작성(결제가 전제) · 소비 내역 · 회고(결제 대조가 전제)
- [ ] 잠금 사유를 **아동 언어로** 표시 — *"카드가 오면 열려요"*. 결함으로 오인되지 않게(AC-2.4와 같은 원칙)
- [ ] 카드 상태 3종(미신청 · 배송 대기 · 사용 가능)을 **구별해 문구를 분기**

- [ ] `src/components/ui/**` 재사용 — 잠금 컴포넌트를 한 곳에 두고 재사용한다

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 카드 배송 대기 중 학습 가능 (AC-8.2)**
- **Given:** 카드 배송 대기 상태
- **When:** 아동이 앱을 연다
- **Then:** **학습·퀴즈·별 획득이 가능**하고 **카드 필요 기능만** 잠긴다.

**Scenario 2: 라우트가 아니라 컴포넌트가 잠긴다**
- **Given:** 잠금 상태
- **When:** 잠긴 기능이 있는 화면에 접근한다
- **Then:** **화면 자체는 열리고** 해당 컴포넌트만 잠긴 상태로 보인다 — 404나 리다이렉트가 아니다.

**Scenario 3: 사유가 아동 언어로**
- **Given:** 잠긴 컴포넌트
- **When:** 아동이 그것을 본다
- **Then:** *"카드가 오면 열려요"* 처럼 **결함이 아니라 대기 상태**로 읽힌다.

## ⚙️ Technical & Non-Functional Constraints

- 🔴 **라우트 유지:** 라우트 그룹 구조를 바꾸지 않는다(REQ-TEC-001) — 그룹을 건드리면 게이트 G3의 검사 대상이 흔들린다
- 🔴 **열어 둘 것을 먼저 정한다:** 학습·퀴즈·별 획득은 **카드와 무관**하다. 이것까지 잠그면 아동이 온보딩 직후 할 것이 없다
- **문구:** 아동 언어 · 결함으로 오인되지 않게(CON-REG-02 · REQ-NF-014)
- **재사용:** 잠금 컴포넌트를 한 곳에 — 화면마다 따로 만들면 상태 판정이 갈라진다
- **범위:** 카드 상태 갱신은 FR-025, 카드 신청은 FR-012
