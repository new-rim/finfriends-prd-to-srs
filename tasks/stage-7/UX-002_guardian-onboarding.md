## 🎯 Summary

- **기능명:** 보호자 온보딩 5단계 화면(Stepper · **재개 상태 표기**)과 세션이 필요 없는 `(public)` 화면(랜딩 · 로그인 · 동의 안내).
- **목적:** `FR-012`가 매 단계를 DB에 커밋해 두었으므로, 화면은 **어디까지 했는지 보여 주고 이어서 시작**하게 하면 된다 — 재입력 0건(AC-8.1)의 사용자 쪽 절반이다.
- **왜 한 이슈인가:** 두 화면이 **같은 라우트 그룹 경계**(`(public)` ↔ `(guardian)`)를 사이에 두고 이어지고, 로그인→온보딩 흐름이 하나다.

### 🎨 디자인 명세는 `UX-002d`로 분리되었다

개정 3.1은 디자인과 화면 구현을 한 이슈로 합쳤고, 그 대가를 스스로 이렇게 적어 두었다.

- 🔴 **DoD가 두 묶음이다** — 「디자인 완료」와 「구현 완료」를 나눠 체크한다.
- 🔴 **FR 선행이 생겼다** — 통합 전에는 디자인이 개발과 무관하게 먼저 갈 수 있었다.

**UXUI 통합 단계에서 그 두 묶음의 경계를 두 태스크로 승격했다.** 디자인 명세는 `UX-002d`(Stage 0 · D+3~5 · **FR 선행 0건**)가 지고, 이 이슈는 **화면 구현만** 진다.

| | 디자인 명세 `UX-002d` | 화면 구현 `UX-002` (이 이슈) |
| --- | --- | --- |
| 무엇 | 플로우·Stepper 시각 규칙·재개 표기 문구·실패 사유 문구·PWA 배너 배치·`(public)` 3종 레이아웃 | 그 명세를 화면으로 구현 · `FR-012` 반환값 바인딩 · 계측 |
| 선행 | `UX-001` | `FR-001` · `FR-010` · `FR-012` · **`UX-002d`** |
| 판정 | 산출물 확정 (DoD 디자인 묶음) | **아래 AC 3건 + DoD 8항목 전건** |

> AC와 DoD는 **하나도 옮기지 않았다.** 행위 기준은 동작하는 화면이 있어야 판정되고, DoD 8항목은 전부 *만들어진 화면의 성질*을 묻기 때문이다. 근거: `docs/uxui-integration-stage/DECISION_LOG.md` MINOR-2.

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 단계 재개 표기 (AC-8.1)**
- **Given:** 온보딩 2단계까지 진행 후 종료
- **When:** 다음 날 재진입한다
- **Then:** **직전 단계에서 이어서 시작**하는 화면이 뜨고 **재입력 항목 0건**이다.

**Scenario 2: 외부 실패 사유 표기 (ACE-8.1)**
- **Given:** 카드 신청 단계에서 외부 API 실패
- **When:** 오류 화면이 뜬다
- **Then:** 사유가 **사용자 언어**로 표시되고, 재진입 시 입력값이 남아 있음을 알 수 있다.

**Scenario 3: 세션 없는 공개 화면**
- **Given:** 로그인하지 않은 방문자
- **When:** 랜딩·동의 안내에 접근한다
- **Then:** **정상 렌더**된다 — `(public)`은 세션이 필요 없다.

## ⚙️ Technical & Non-Functional Constraints

- **경계:** `(public)`은 세션 불필요, `(guardian)`은 필수 — 분리는 **조건문이 아니라 디렉터리**다(§3.2)
- **판정 금지:** 단계 상태를 화면이 계산하지 않는다 — `FR-012`가 반환한 값을 그린다
- **스타일:** `globals.css` 단일 진입점 · `src/components/ui/**` 재사용 (게이트 G5)
- **지표:** 3단계 이탈률 ≤ 30%(AC-8.3)는 **운영 지표** — 이 이슈는 계측 가능하게만 만든다
- **범위:** 액션은 FR-012, PWA 설치성은 FR-031, 퍼널 집계는 FR-026
