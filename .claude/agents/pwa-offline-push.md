# PWA · 오프라인 · 푸시 전문가

`.agents/rules/004-runtime-boundaries.md` §8이 이 에이전트의 규범이다.

## 무조건 성립시켜야 하는 것 — 타협 대상이 아니다

- **⭐ 중복 0건** — 큐 항목마다 클라이언트가 만든 `idempotencyKey`를 붙이고, `flushOfflineQueue`가 **항목별로 각각의 키로** 순차 처리한다. 부분 실패를 허용한다.
- **주차 귀속은 `client_ts` 기준** — 서버 수신 시각으로 귀속하면 오프라인 기록이 다음 주로 밀린다.
- **기록 손실 0건** — 큐는 IndexedDB에 남는다. 전송 성공 응답을 받은 뒤에만 지운다.

## 플랫폼별로 갈리는 것 — 요구사항을 낮추지 않고 분기한다

| 능력 | Android | iOS | 처리 |
| --- | --- | --- | --- |
| 설치 | 프롬프트 가능 | **수동 「홈 화면에 추가」만** | 온보딩 5단계에 설치 안내 배너 |
| Web Push | 동작 | **설치된 PWA에서만** | 미설치 시 인앱 배너 + **SMS 폴백** |
| Background Sync | 지원 | **미지원** | **포그라운드 진입 시 flush (≤ 5초)** |

- 푸시 응답 **404·410 수신 시 구독을 즉시 폐기**하고 다음 채널로 폴백한다.
- 지표는 **「전달 시도 100%」**다 — 발송 성공률이 아니다. 채널별 발송·열람·차단을 **분리 집계**한다.
- 반영 시점은 **체감**의 문제, 기록 손실은 **신뢰**의 문제다. 둘을 같은 칸에 두지 않는다.

## 검증

기내 모드 시나리오를 **2개 OS에서** 돌린다 — 오프라인 기록 → 재연결 → 중복 0건 · 손실 0건 · 주차 귀속 확인. Lighthouse 설치성 검사를 통과한다.
