# 프로토타입 검수 보고 — 여덟 라운드의 기록

**문서 ID:** REPORT-AZTKS-FINFRIENDS-001
**작성:** 2026-08-27 · **대상:** 시각 프로토타입 3화면 (`(guardian)/tree` · `(child)/learn/spend` · `(child)/retro`)
**상태:** ✅ **1~8라운드 종료** — 지적 전건 반영 완료

> **이 문서가 답하는 것** — *"화면은 다 만들었는데 왜 계속 불합격이 나왔나."*
> 각 라운드의 검토자 반환 원문은 `aztks-review-{2,3,4,5,6,7,8}.md`에 그대로 있다. 이 문서는 그것을
> **유형별로 묶어 해설**한 것이다.

---

## 1. 무엇을 채점했나

검토자(`aztks-agent`)는 다섯 가지를 본다. 쉬운 말로 옮기면 이렇다.

| 항목 | 묻는 것 |
| --- | --- |
| **A 알아서** | 챙겨야 할 걸 다 챙겼나 |
| **Z 잘** | 제대로 만들었나, 틀린 값은 없나 |
| **T 딱** | 원래 하려던 것과 어긋난 데 없나 |
| **K 깔끔** | 쓸데없는 게 남아 있지 않나 |
| **S 센스** | 다음 사람이 바로 이어받을 수 있나 |

`P` 통과 · `C` 걸림. **하나라도 `C`면 불합격**이다.

---

## 2. 채점표 — 8회 전체

| 회차 | 대상 | A | Z | T | K | S | 판정 |
| :-: | --- | :-: | :-: | :-: | :-: | :-: | :-: |
| **1차** | 계획서 | C | C | C | C | C | 미달 |
| **2차** | 만든 것 | **P** ⬆ | C | C | C | **P** ⬆ | 미달 |
| **3차** | 만든 것 | P | C | C | C | **C** ⬇ | 미달 |
| **4차** | 만든 것 | P | C | **P** ⬆ | **P** ⬆ | C | 미달 |
| **5차** | 만든 것 | P | C | P | **C** ⬇ | C | 미달 |
| **6차** | 만든 것 | P | C | P | C | **P** ⬆ | 미달 |
| **7차** | 만든 것 | P | C | P | **P** ⬆ | P | 미달 *(1건)* |
| **8차** | 만든 것 | P | **P** ⬆ | P | C | C | 미달 *(2건)* |

**`Z`(제대로 만들었나)는 7회 내내 걸리다 8차에 처음 통과했다.** 매번 다른 게 나왔다.
**`A`는 2차 이후 일곱 번, `T`는 4차 이후 다섯 번 연속 통과**다. `T`가 이 목표의 핵심 축이다.

**걸린 항목 수는 계속 줄었다** — 5 → 3 → 3 → 2 → 3 → 2 → **1** → 2.
7·8차 지적은 **조사 하나**와 **문서 두 줄** 수준이었고, 평가자가 두 번 다
*"본 개발 착수를 막지 않는다"* 고 판정했다.

## 3. 불합격 사유 — 다섯 유형

### 유형 ① 세 화면이 따로 놀았다 *(1·2·3차 · 가장 무거움)*

가장 오래 걸린 항목이다. 화면은 다 만들었는데 **한 아이의 이야기로 읽히지 않았다.**

| 회차 | 무엇이 문제였나 |
| :-: | --- |
| **1차** | 세 화면이 **각자 다른 아이**의 데이터를 봤다 |
| **2차** | 같은 아이로 묶었는데 **숫자가 안 맞았다** — 학습 화면은 "1개 배웠어요", 부모 화면은 "2개 배웠음" |
| **3차** | 회고에서 별을 받았는데 **그게 나무로 간다는 말이 없었다.** 정작 그 문구를 **퀴즈 화면**에 넣어뒀다 |

**3차가 가장 아팠다.** PRD가 정한 「실천으로 인정되는 행동」은 **미션 승인 · 소비 회고 · 위시리스트**
셋이고 퀴즈는 거기 없다. 나는 그 사실을 알고 *"퀴즈에 실천을 걸지 말라"* 는 규칙까지 적어놨는데,
**나무로 잇는 문구는 퀴즈에만 넣고 정작 회고는 비워뒀다.**

> **왜 중요한가** — 프로토타입을 보여주며 *"우리 서비스는 이렇게 돌아갑니다"* 라고 말하려면
> 세 화면이 한 줄로 이어져야 한다. 따로 놀면 **세 장의 남의 집 사진**이다.

### 유형 ② 정해놓고 화면에 안 걸리게 해뒀다 *(4차)*

색·글자크기·행간을 정성껏 정해놓고 **적용이 안 되는 자리**에 써뒀다.

> 안방에 둔 물건을 현관에서 쓰려 한 셈이다. 안 보인다.

결과 — **아동 화면 배경색 · 18px 글자 · 넓은 행간이 전부 안 걸리고 있었다.**
게다가 간격·글자비율 값은 **아무 데서도 안 쓰였다.** 계획서에 "3가지 축으로 아이·부모 화면을
다르게 한다"고 적어놓고 실제로는 **색 하나만** 작동했다.

> **왜 중요한가** — 이건 **눈으로 봐서는 모른다.** 화면은 뜨고, 값은 파일에 있다.
> 본 개발에 들어가 한참 뒤에 *"왜 아이 화면이 부모 화면이랑 똑같지?"* 하고 발견했을 문제다.

### 유형 ③ 문서와 코드가 갈렸다 *(3·4·5차)*

**내가 숫자를 지어냈다.**

| | 값 |
| --- | --- |
| 계획서 | 「잘 써요」 학습 **1편** · 퀴즈 **1개** |
| 내 코드 | 학습 **2** · 퀴즈 **4** |

검토자 표현이 정확했다.

> *"다음 사람이 계획 문서를 확정 출처로 읽으면 1/1을 구현한다.
> **문서·화면·코드 셋 중 어느 것이 권위인지 지금 갈려 있다.**"*

> **왜 중요한가** — 이 프로토타입의 목적이 *"이후 본격 개발을 이어가는 것"* 이다.
> **근거가 세 갈래로 갈리면 이어받을 수가 없다.**

### 유형 ④ 군더더기 *(3·5차)*

- 만들어놓고 **아무 데서도 안 쓰는** 상수
- 같은 문구("이번 달")를 **세 군데**에 따로 적음
- 한 화면에 **같은 내용이 두 번** — 위 카드에 "학습 2회 남음", 아래 설명에도 "학습 2회 남음"

마지막 건 **부모가 화면을 3분 안에 확인해야 한다**는 목표에 역행한다. 같은 걸 두 번 읽게 하니까.

### 유형 ⑤ 🔴 검사 도구 자신이 거짓말을 했다 *(5차)*

**이번엔 만든 것이 아니라 그것을 채점하는 도구가 틀렸다.**

```
서버 꺼져 있음 (응답 000)
        ↓
✅ L1 통과 · "HTTP /tree=200"      ← 옛 기록을 읽고 통과를 냄
```

**「측정 안 함」과 「측정해서 통과」를 구분하지 못했다.**

지금까지 보고한 「6/6 통과」는 **전부 서버를 띄우는 정식 절차로 돌린 실측**이었다.
그럼에도 도구가 이 둘을 구분 못 하는 것은 결함이다 — 언젠가 절차 없이 돌린 결과가
근거로 쓰이면 **그때는 거짓이 된다.**

지금은 이렇게 나온다.

```
❌ L1  미측정 — HTTP 캐시가 541초 전 것이다(상한 120초)
✅ L1  … (실측 0초 전)              ← 통과할 때는 근거를 함께 적는다
```

### 유형 ⑥ 🔴 시각 프로토타입인데 그림이 없었다 *(6차)*

계획서 §5.4가 *"**CSS/SVG 3단계 도형**(씨앗·새싹·나무)으로 그린다"* 고 **확정**했는데,
실제로는 「새싹」이라는 **글자만** 냈다.

```
$ grep -rn "svg|circle|clip-path" app/ src/
0건
```

**간판 화면인 성장 나무에 나무가 없었다.** PRD 부록 B의 「나무 층」이 낱말로만 서 있었다.

> **왜 다섯 라운드 동안 아무도 못 잡았나** — 이게 더 중요하다.
> 렌더 결과를 뜨는 내 도구(`html-to-text.mjs`)가 **`svg` 태그를 아예 안 봤다.**
> 그래서 도형이 **있든 없든 기록에 흔적이 남지 않았다.**
> 검토자는 브라우저가 없어 그 기록이 유일한 근거다 — **계측기가 못 보는 것은 몇 번을 돌려도 안 잡힌다.**

**조치 후 스스로 하나 더 발견했다.** 도형을 넣고 검사를 붙이니 **씨앗·새싹 둘만** 잡혔다.
기본 시나리오에 승급 완료된 칸이 없어 **「나무」 단계를 볼 자리가 없었다.**
3단계를 만들어놓고 하나를 못 보여주면 §5.4를 절반만 만족한 것이다.

```
씨앗 3 · 새싹 5 · 나무 1        ← 검수용 상태를 더해 3단계 전부 확인
L5: 단계 도형 3/3 (SEED/SPROUT/TREE)
```

### 유형 ⑦ 한국어 조사를 고정했다 *(7차)*

`narrative.ts`가 `{단계}**이** 됐어요`로 「이」를 고정해 **「나무이 됐어요」**를 냈다.

6차까지 안 보인 이유가 있다 — 기본 화면엔 **「새싹」(받침 있음)** 만 나와 「새싹이」가 맞았다.
6차에서 3단계 도형을 넣으며 *"「나무」 단계를 볼 자리가 없다"* 고 판단해 검수용 화면을
추가했고, **그 화면이 이 버그를 드러냈다.**

> **걸린 자리가 가볍지 않다** — 이 문장은 부모가 화면을 열자마자 보는 **첫 줄**이고,
> PRD가 *"누적 숫자는 성장의 증거가 못 된다"* 며 이 서비스의 존재 이유로 삼은 자리다.
> **「나무」는 승급의 종점** — 가치 전달의 절정에서 조사가 틀렸다.

**계획서도 함께 고쳤다.** 템플릿이 `{단계}이 됐어요`로 **「이」를 고정**하고 있었다 —
문서를 따르면 「나무이」가 유지된다. **문서 자체가 틀린 한국어를 지시**하고 있었다.

### 유형 ⑧ 문서를 고치다 절반만 고쳤다 *(8차)*

7차에서 검수용 화면 목록을 계획 §14.2에 표로 더했는데, **§0.3과 규칙 파일에 남은
「링크 3개만」을 안 고쳤다.** 같은 사실을 세 곳에 적어두고 **한 곳만 갱신한 것**이다.

> 유형 ③(문서와 코드가 갈렸다)의 **잔여**다. 고칠 때 한 곳만 보면 이렇게 남는다.

## 4. 왜 여덟 번이나 떨어졌나

**통과선을 일부러 올렸기 때문이다.**

| | 기준 |
| --- | --- |
| 검토자의 원래 규칙 | 심각한 문제가 없으면 **합격** |
| 이번에 적용한 기준 | 걸리는 게 **하나도 없어야** 합격 |

**원래 규칙이면 1차부터 8차까지 전부 「합격」이었다.** 5·6·7·8차 검토자가 반환문에
*"기본 규칙이면 GO"* 라고 직접 적었다.

그랬다면 위의 여덟 유형을 **전부 안고** 본 개발에 들어갔을 것이다.
특히 유형 ②와 ⑤는 눈으로 봐서 알 수 없다 — 화면은 뜨고, 검사는 통과라고 하니까.
유형 ⑥은 눈으로 보면 알 수 있었지만, **검토자에게 건네는 기록에 그 정보가 없었다.**

## 6. 정리 — 떨어진 이유의 성격

**「기능이 안 된다」로 떨어진 적은 한 번도 없다.** 화면은 1차부터 다 떴고 빌드도 통과했다.

떨어진 건 전부 **「이어지는가」** 였다.

| | |
| --- | --- |
| 세 화면이 **한 이야기로** 이어지는가 | 유형 ① |
| 정한 값이 **화면까지** 이어지는가 | 유형 ② |
| 계획서가 **코드로** 이어지는가 | 유형 ③ |
| 검사 결과가 **사실과** 이어지는가 | 유형 ⑤ |
| 확정한 사양이 **그림으로** 이어지는가 | 유형 ⑥ |
| 문장이 **읽히는 한국어로** 이어지는가 | 유형 ⑦ |
| 한 곳을 고칠 때 **나머지까지** 이어지는가 | 유형 ⑧ |

이 프로토타입의 목적이 *"이후 본격 개발을 이어가는 용도의 시각적 확인"* 이었으므로,
**정확히 그 지점만 계속 걸린 셈이다.**

| 라운드 | ✅ **8회 종료** — 지적 전건 반영 *(상한 5→7→8 · 사유는 `aztks-review-5.md`·`-8.md`)* |

**8차 최종 판정은 `A:P Z:P T:P K:C S:C`이고, 남은 2건은 반영을 마쳤다.**
`T`가 이 목표의 핵심 축이다 — *"세 화면이 서비스의 형태·고객 경험·가치 전달을 담은 흐름인가"*.
8차 평가자의 문장이 그 답이다.

> *"3화면만 본 사람이 **「아이가 배우고 실천하면 → 부모가 행동 변화를 본다」를 한 줄로 읽는다**."*

### 검사 항목이 라운드마다 늘었다

떨어질 때마다 **같은 실수가 다시 안 나오도록 검사를 붙였다.** 이것이 여섯 라운드의 실질 소득이다.

| 회차 | 추가한 검사 | 막는 것 |
| :-: | --- | --- |
| 착수 | L1~L5 | 로컬 완결 · 빌드 · 스타일 · 접근성 · 문구 일치 |
| 2차 | **L6 불변식** | 세 화면의 숫자가 갈라지는 것 |
| 4차 | **스코프 이탈 · 미소비 토큰** | 정해놓고 화면에 안 걸리는 것 |
| 5차 | **캐시 신선도** | 계측기가 미측정을 통과로 적는 것 |
| 6차 | **3단계 도형 존재** | 확정한 사양이 그림 없이 글자로만 나는 것 |
| 7차 | **조사 12조합 검사** | 「나무이 됐어요」 같은 문장 오류 |
| 8차 | **라벨 전수 조사 검사** | 헬퍼를 만들고 한 자리에만 적용하는 것 |

**이 검사들은 프로토타입이 끝나도 남는다.** 본 개발에서 같은 실수가 나면 그때도 걸린다.

## 8. 종료

**8라운드로 검수를 마쳤다.** 8차 지적 2건(문서 2줄 · 코드 1줄)은 **반영을 완료**했고,
해소 근거는 평가자가 지정한 검증 명령으로 직접 확인했다(`grep "링크 3개"` 0건 · `npm test` 7건).

**남은 CONCERN은 없다.** 다만 이것이 「5축 전부 `P`」 판정을 받았다는 뜻은 아니다 —
9라운드를 열지 않았기 때문이다. 정확히 적으면 이렇다.

| | |
| --- | --- |
| 8차 판정 | `A:P Z:P T:P K:C S:C` |
| 그 2건 | **반영 완료** · 해소 근거를 명령으로 확인 |
| 9차 재판정 | **받지 않음** — 사용자가 화면 검토로 방향을 정했고, 평가자가 두 건 모두 「착수를 막지 않는다」고 판정했다 |

**본 개발로 넘길 때 유의할 것 하나** — `src/contracts/narrative.ts`와
`app/(guardian)/tree/page.tsx`는 **`FR-030`으로 승계되는 파일**이다.
8차 평가자가 *"FR 첫 커밋에 포함시켜라"* 라고 적었다.
