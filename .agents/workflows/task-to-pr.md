# 워크플로우 — 태스크 → PR

> 대상: GitHub 이슈 `#1`~`#46` 중 1건. **한 번에 한 태스크.** 여러 태스크를 한 브랜치에 섞지 않는다.

## 단계

| # | 단계 | 스킬 / 에이전트 | 통과 조건 |
| :-: | --- | --- | --- |
| **1** | **착수 가능성 판정** | `task-kickoff` | 선행이 닫혔고 **착수 차단(`T-*`·`D-TEC-*`)이 없다.** 있으면 **여기서 멈추고 무엇을 누가 답해야 하는지 보고**한다 |
| **2** | **근거 읽기** | — | 태스크 파일 `References`의 SRS 절 **전건** 열람. 요구사항 ID·규제 계층·런타임 경계를 특정했다 |
| **3** | **브랜치** | `gitflow-commit` | `feat/<이슈번호>-<슬러그>`. `master` 아님 |
| **4** | **AC → 테스트** | `tdd` · `playwright-cli` | 태스크 파일의 BDD/GWT 시나리오 **전건**이 실패하는 테스트로 존재한다 |
| **5** | **구현** | 아래 라우팅 표 | 테스트가 통과한다 |
| **6** | **게이트** | `prebuild-gate-authoring` | `npm run prebuild` 통과. 새 규제 항목이면 **위반 주입 테스트**까지 |
| **7** | **환경** | `env-and-secrets` | 새 환경 변수가 있으면 스코프가 맞고 `.env.example`에 있다 |
| **8** | **PR** | `gitflow-commit` | draft PR 본문에 근거·검증·**승인 필요 항목**이 있다 |

## 5단계 구현 라우팅

| 무엇을 만드나 | 위임 |
| --- | --- |
| Server Action · Route Handler · RSC · 라우트 그룹 · 캐시 태그 | `nextjs-server-boundary` 에이전트 + `server-action-contract` 스킬 |
| Prisma 스키마 · RLS 정책 · 마이그레이션 · `pg_cron` 배치 | `supabase-postgres` 에이전트 + `rls-and-migration` 스킬 |
| `prebuild` 게이트 | `prebuild-gates` 에이전트 |
| Service Worker · 오프라인 큐 · 푸시 · SMS 폴백 | `pwa-offline-push` 에이전트 |
| 화면 · 컴포넌트 | `shadcn` + `vercel-composition-patterns` 스킬 — **SRS §6.8 대응표에서 먼저 찾는다** |
| 판정 로직 | `src/domain/**` 순수 함수 + 단위 테스트 |

## 멈춰야 하는 신호

아래를 만나면 **진행하지 않고 보고**한다. 「일단 가정하고」 만든 것은 답이 나온 뒤 재작업이 된다.

- 착수 차단(`T-1`~`T-4` · `D-TEC-1`~`8`)이 이 태스크에 걸려 있다
- SRS에 근거가 없는 판단을 해야 한다 — **SRS를 먼저 고칠지 논의**한다
- 요구사항을 지키려면 성능 예산을 넘겨야 한다 — **§8 처리 순서**를 적용하고 그래도 안 되면 보고
- 게이트를 끄거나 동의 판정 지점을 줄여야 「깔끔해진다」 — **그것은 수정이 아니다**
- 규제 계층 1·2를 애플리케이션 코드로 지켜야 한다 — 스키마·제약·게이트로 옮길 방법을 먼저 찾는다
