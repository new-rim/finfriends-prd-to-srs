# 에러 진단 7단계

대상: **$ARGUMENTS**

## 0. 이 저장소의 단골 원인을 먼저 대조한다

| 증상 | 흔한 원인 |
| --- | --- |
| 조회 결과가 **비어 있다**(에러 없이) | RLS가 정상 동작 중 — `app.guardian_id`가 설정되지 않았거나 **쿼리가 트랜잭션 밖**에 있다 |
| `permission denied for schema pii` | **정상이다.** `app`↔`pii` 조인은 막혀 있다 — 함수 3개로 우회 |
| prepared statement 관련 오류 | transaction 모드 풀러(6543)에서 prepared statement 사용 |
| 부하 시 커넥션 고갈 | `connection_limit=1` 누락 · 요청용이 5432를 가리킴 |
| 동의 상태가 낡은 값으로 보인다 | `(child)` 경로에서 `noStore()` 누락 — 라우트가 정적으로 굳었다 |
| 같은 요청이 두 번 반영됐다 | `idempotencyKey` 누락 또는 서버 생성 |
| `balance_after`가 어긋난다 | 애플리케이션에서 잔액을 계산해 넣었다 — 단일 SQL 원자 기입으로 바꾼다 |
| 빌드가 갑자기 실패 | `prebuild` 게이트 위반 — 메시지의 요구사항 ID를 읽는다 |
| 배치가 조용히 멈춤 | `pg_cron`·`pg_net` 미활성 또는 최근 성공 시각 감시 부재 |
| iOS에서만 큐가 안 나간다 | Background Sync 미지원 — **포그라운드 진입 flush**가 있는지 |

## 1. 현상 정의
관찰된 증상·재현 조건·에러 메시지 원문·스택트레이스를 **그대로** 옮긴다.

## 2. 맥락·범위 탐색
관련 파일·데이터 흐름·호출 경로를 지도화한다. `Grep`/`Glob`으로 연관 심볼과 사용처를 확인한다. **어느 런타임 경계에서 터졌는지**(Client / Middleware / RSC / Server Action / Route Handler / `pg_cron`)를 먼저 특정한다.

## 3. 문제 핵심 특정
근본 원인을 증거 기반으로 좁힌다. 가설이 여러 개면 각각의 근거와 **반증**을 나열한다.

## 4. 쉬운 말로 요약
전문용어를 줄여 「무엇이 왜 잘못되었는가」를 한 문단으로.

## 5. 수정 포인트
수정할 지점을 `파일:라인`으로 나열하고 각각의 이유를 적는다. **규제 계층 1·2에 걸린 것이면 애플리케이션 코드가 아니라 스키마·제약·게이트에서 고칠 수 있는지 먼저 검토한다.**

## 6. 수정
원저자의 의도를 보존하며 고친다. **불필요한 리팩터링을 같이 섞지 않는다** — 한 번에 한 가지.

🔴 **다음은 「수정」이 아니다** — 게이트를 끄는 것 · 동의 판정 지점을 줄이는 것 · RLS를 끄는 것 · `revalidatePath("/")`로 캐시 문제를 덮는 것. 증상이 사라져도 요구사항이 깨진다.

## 7. 후속 제안
테스트 추가·로깅 보강·리팩터링을 **별도 작업으로** 제시한다. 지금 반영하지 않는다.
